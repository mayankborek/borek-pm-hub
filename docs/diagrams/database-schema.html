Database schema

Eight tables, every column shown. Every project defines its own statuses; a task belongs to one project, has one of that project's statuses and may be assigned to one user. project_members links users to projects. Each task also has comments, attachments (files or links) and an activity history. Version columns provide optimistic locking.

Nothing is deleted

Archive, do not drop

Projects and tasks carry archived_at. No foreign key cascades, so deleting a parent row is blocked while children exist.

The database is the guard

Rules live in constraints

Unique project code, unique task key per project, unique status name per project, progress 0-100, and a task can only use a status of its own project. Python cannot bypass them.
